🏗️ 3D Engine – Architecture Notes

Status (30 Jul 2026)
Core architecture established. The engine has moved beyond a toy renderer into a coherent simulation framework with stable ownership.

🎯 Why This Engine Exists

Build an engine from first principles.

Not to imitate Unreal or Unity, but to create a simulation framework that is:

Easy to reason about
Architecturally consistent
Predictable
Pleasant to extend

Every abstraction must earn its place.

🧠 Core Philosophy

Before writing code, ask:

❓ What is it?
👤 Who owns it?
⚠️ Am I introducing two truths?

Golden rules:

✅ One source of truth.
✅ Ownership determines responsibility.
✅ Simulation drives rendering.
✅ Understanding before optimization.
🌍 World Model
Engine
│
├── Timer
├── Input
├── Renderer
└── Scene
      │
      ├── Physics
      └── Entities
            │
            ├── Transform
            ├── Mesh
            ├── Layers
            ├── Tags
            └── Name + ID

Ownership flows downward.

Do not casually move responsibilities.

📦 Responsibilities
Engine
Runs the application
Coordinates systems
Scene
Owns the world
Owns Physics
Assigns IDs
Orchestrates updates

🚫 Does not perform physics.

Entity

Represents something that exists.

Owns:

Transform
Mesh
Layers
Tags
Name
ID
Mesh

Geometry.

Nothing else.

Never owns:

Position
Physics
Gameplay
IDs
Names
Renderer

Consumes world state.

Never becomes world state.

🏷️ Naming
Mesh::cube()

↓

Entity::cube()

↓

Scene::add_entity()

Mesh creates geometry.

Entity defines meaning.

Scene assigns identity.

Example:

Cube_4
RigidBody_2
Entity_17
